# FABL 테스트

**F**rame · **A**im · **B**uild · **L**ink — 네 가지 업무 모드의 머리글자다.

나는 일을 **어떤 순서로** 잘할까. 12개 업무 상황에서 무엇을 먼저 보고, 어떻게 판단하고,
누구와 결과를 만드는지 보고 24개 업무 유형 중 하나를 돌려준다.

성격을 묻지 않는다. 점수의 높낮이도 매기지 않는다. **먼저 쓰는 순서**만 본다.

## 네 가지 업무 모드 · FABL

| | 모드 | 질문 |
|---|---|---|
| **F** | Frame · 해석 | 무슨 일이 벌어지고 있지? |
| **A** | Aim · 판단 | 무엇을 먼저 해야 하지? |
| **B** | Build · 실행 | 어떻게 결과로 만들지? |
| **L** | Link · 조율 | 누구와 함께 움직이지? |

먼저 쓰는 세 가지의 **순서**가 유형이 된다. 4개 중 3개를 순서까지 세면 24가지다.
같은 강점도 순서가 다르면 다른 유형이다 — `FAB`(분석추진형·레오나르도 다빈치)와
`FBA`(해결검증형·마리 퀴리)는 쓰는 힘이 같고 순서만 다르다.

## 두 층으로 나뉜다 — 유형(선호)과 판단 체크(정답)

이 테스트는 성격이 두 다른 것을 한 화면에서 다룬다. 섞으면 둘 다 망가져서 분리했다.

| | 유형 12문항 | 판단 체크 8문항 |
|---|---|---|
| 재는 것 | 자주 쓰는 **순서** | 판단의 **타당성** |
| 정답 | 없다. 네 선택지가 모두 타당하다 | 있다. 하나가 방어 가능하게 더 낫다 |
| 척도 | ipsative(자기참조) | normative(사람 간 비교 가능) |
| 공유 | 유형만 공유된다 | 결과 화면 안에만 둔다 |

**유형 점수로는 잘하는지 알 수 없다.** 설계가 그렇다. 채점이 각 역량 점수를 본인 평균으로
나누기 때문에(`calculate()`) 합이 구조적으로 고정된다. 실제로 재보면 아무렇게나 클릭한
사람까지 포함해 여섯 응답자가 전부 50점 만점에 33.5~35.1 안에 들어온다. 유형은 갈리지만
총점은 안 갈린다. "당신 안에서 이 축이 높다"는 말은 되지만 "남보다 낫다"는 말은 원리적으로
안 되는 값이다.

그래서 정답 키가 있는 층을 따로 뒀다(`src/keyed.js`). 각 문항의 정답 근거는 지어내지 않고
역량 카드의 잘함·부족·혼동 주의 문장에서 가져왔고, 틀리면 그 원칙을 해설로 보여준다.
LLM 을 쓰지 않아 서버 비용이 없고 답변이 밖으로 나가지 않는다.

**실력 점수는 공유 카드에 넣지 않았다.** 낮게 나온 결과를 공유할 사람은 없고, 그러면
유형까지 안 퍼진다. MBTI 가 퍼지고 IQ 테스트가 안 퍼지는 이유와 같다.

## 두 가지 코스

| | 문항 | 형식 | 소요 |
|---|---|---|---|
| **짧은 코스** (기본) | 12개 + 판단 체크 8개 | 객관식만 | 2~3분 (+2분) |
| **정밀 코스** | 20개 상황 | 객관식 8 · 혼합형 8 · 3단계 대화 4 | 6~8분 |

짧은 코스의 12개 상황은 임의로 고르지 않았다. 각 선택지의 지배 모드를 계산해
**네 모드를 모두 가르는 9개**와 세 모드를 가르는 3개를 골랐다
(`SHORT_SCENARIO_INDEXES`, `src/main.js`). 두 코스는 같은 채점을 쓴다 —
선택지의 역량 가중치를 누적하고, 모드별 평균을 내고, 상위 3개의 순서를 코드로 만든다.

## 공유

결과가 나오면 주소창이 `/t/FAB/?a=...` 로 바뀐다. 이 링크는

- **코드만 있으면** 유형 카드만 보여준다. 답변이 없는데 레이더를 그리지 않는다 — 없는 점수를 지어내지 않기 위해서다.
- **답변까지 실려 있으면** 레이더까지 그대로 복원한다.

미리보기 카드는 유형마다 다르다. 카카오톡·X 같은 크롤러는 자바스크립트를 실행하지 않고
해시(`#`)도 읽지 않으므로, 빌드 때 **유형별 실제 HTML 24장과 OG 이미지 24장**을 찍는다.

```
npm run build
#  1. scripts/build-og.mjs   → public/og/<CODE>.png 24장 + default.png
#  2. vite build             → dist/
#  3. scripts/build-seo.mjs  → dist/t/<CODE>/index.html 24장 + robots.txt + sitemap.xml
```

OG 이미지는 SVG 를 직접 만들어 `@resvg/resvg-js` 로 래스터화한다. 폰트는
`scripts/fonts/` 에 동봉했다 — **폰트를 못 찾으면 에러 없이 글자만 사라지므로**
빌드 후 `public/og/` 를 눈으로 확인한다.

## 실행

```bash
npm install
npm run dev
```

## 데이터

모든 응답은 브라우저 안에서만 처리한다. 서버로 보내지 않는다.
진행 중 답변은 `sessionStorage`, 완료 결과는 `localStorage` 에 최근 30회까지 남는다.
결과 화면에서 JSON 으로 내려받고 시작 화면에서 다시 불러올 수 있다.

이 공개판에는 서버가 없다. 원본에 있던 `/api/evaluate`(OpenAI 호출)는 옮기지 않았고,
심층 대화 채점은 브라우저 로컬 규칙으로만 한다. 그래서 화면에서 "AI 평가자"라고
말하지 않는다 — 정규식 규칙 매칭이지 AI 가 읽는 것이 아니다.

원본의 판단 품질 패널은 LLM 이 채워주던 신호에만 의존해서, 공개판에서는 영원히
렌더되지 않는다. 그 역할은 정답 키가 있는 판단 체크가 대신한다.

## 인물 이미지

`public/people/` 의 24장은 **AI 로 생성한 이미지**다. 실존 인물의 사진을 가져온 것이 아니다.
`scripts/prepare-people-assets.sh` 에 생성 경위가 남아 있다.

## 쓰지 말아야 할 곳

낮은 점수는 능력 부족을 뜻하지 않는다. 자주 쓰는 순서를 볼 뿐이다.
**채용·인사평가의 근거로 사용하지 않는다.** 재미와 자기 이해를 위한 도구다.
